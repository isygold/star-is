Runtime Flow — How lossless.dll Gets Used

U User places lossless.dll on device
→
UI Enable "Custom FrameGen DLL" + file picker
→
UI Save container: lsfgCustomDllEnabled=true
→
JV LsfgManager.ensureLayerInstalled()
→
JV installCustomDll() → copy to layer dir
→
JV Set env LSFG_DLL_PATH=...
→
N Wine starts → Vulkan loads lsfg layer
→
N Layer reads lossless.dll → extracts shaders
→
✓ Frame generation active

Fix Runtime Wiring — callbacks that actually do things

XServerDisplayActivity.java

FIX Implement onApplyLsfg body

Currently empty (// LSFG settings changed - apply to the running environment). Since runtime reconfiguration of a Vulkan layer is not possible (layers are loaded at vkCreateInstance), this should write the current params to a config file that the layer can read on the next frame, OR show a persistent "restart required" indicator.

Best approach: Write multiplier/quality/flow-scale to /tmp/lsfg_config.txt for the layer to poll
XServerDisplayActivity.java

FIX onLsfgToggle → show toast

Currently only flips local state (MutableStateFlow). Since Vulkan layers can't be hot-toggled, this should show a Snackbar/Toast: "LSFG requires container restart to take effect".

state.onLsfgToggle = () -> {
  boolean next = !XServerDrawerState.INSTANCE.getLsfgEnabled();
  XServerDrawerState.INSTANCE.setLsfgEnabled(next);
  showToast(next ? "LSFG enabled — restart container" : "LSFG disabled — restart container");
};
